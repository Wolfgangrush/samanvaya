## Deserialisation

`json.loads` runs with a `parse_constant` that raises, so `NaN`, `Infinity` and `-Infinity`
are refused rather than admitted into a legal report. YAML is parsed with a `SafeLoader`
subclass that additionally raises on duplicate mapping keys — a duplicate key means the
adviser wrote two answers, and the right response is to accept neither. `!!python/` tags are
refused by `safe_load` and surfaced as a named `DeclarationError`.

## DPDP-gate checklist

The eight Phase-8 gates assume a tool that **processes** personal data. This tool does not:
it reads a hand-authored declaration *about* an organisation and reports conformance. That
distinction is the product's foundation, not a technicality — the author is a practising
advocate, and processing a client's personal data would make him a Data Fiduciary or Processor
in his own right, with his own breach-notification duty under Rule 7 and his own indemnity
exposure. The gates are answered on that footing.

| Gate | Status |
|---|---|
| Consent flag checked before processing | **N/A — nothing is processed.** The tool checks whether consent is *declared*, per DPDP s.6 |
| Lawful-basis tagging in the data model | **N/A.** No client data model exists |
| Retention period enforced (auto-delete) | **PASS by construction.** Nothing is retained. No cache, no history store, no log. The single write is the report file the adviser names |
| DSR endpoints present and authenticated | **N/A.** No endpoints; no service |
| Cross-border transfer gate | **PASS.** No network at runtime. Verified by an install-time dependency audit and a runtime socket tripwire, and by a test asserting no source module imports a network client |
| Children's data path with age-gate | **N/A for processing.** Children's facts are evaluated as *declared* facts under DPDP s.9. Notably, the audit found and fixed a defect where those facts were being **fabricated** rather than declared |
| Breach notification path (72h clock) | **N/A.** The tool holds no personal data to breach. It *checks* the 72-hour Rule 7(2)(b) clock as an obligation |
| Consent withdrawal honoured | **N/A.** No consent is collected by this tool |

**Credential refusal is the load-bearing control here, and it is tested both ways:** six
credential shapes must be caught, and five ordinary prose strings must pass unharmed. The audit
found that `\b` in the secret-name pattern failed to match `my_password=` — because `_` and a
letter are both word characters — and that is fixed.
